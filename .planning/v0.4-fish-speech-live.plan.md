# v0.4 — Studio Quality clones on your local machine

> Clone any voice from a YouTube link. Point at a 30-page document.
> Go to bed. Wake up to a finished narration. Studio quality. Local.
> No cloud. No quotas. No accounts.

## Strategic context

PH launch deferred to ship this milestone first. v0.3's terminal-reactions
story is solid; v0.4 unlocks the **"studio quality on your own machine"**
narrative that nothing in the SaaS market can match (ElevenLabs/Cartesia/
Resemble are paid + cloud + your data leaves your laptop).

User-confirmed strategic decisions baked into this plan:

1. **Fish-speech S2 Pro replaces GPT-SoVITS v2 as the live default.**
   GPT-SoVITS stays available behind `VOICEFORGE_TTS_ENGINE=gpt-sovits-v2`
   for one release, then deletes in v0.5.
2. **The killer demo is overnight batch generation** ("clone Tyson, point
   at chapter 1, sleep, wake up to a Tyson-narrated audiobook"), not
   short-form snippets. `voiceforge note` ships with chunking + progress
   - resume + notify-on-done from day one.
3. **Quality > latency on the live path.** Fish-speech is 2-3× real-time
   on M-series vs GPT-SoVITS's 1.5×. We accept the latency because the
   product story is "takes time, sounds incredible." Pre-rendered packs
   remain the sub-100ms instant path for live event reactions.
4. **Build it right + ample tests + no regressions.** This plan calls
   out test strategy at the same level as code strategy.

## Existing infrastructure we can reuse

The bulk of the fish-speech runtime work is already done in offline
form:

| Asset                               | Location  | What it does                                                                                                                    |
| ----------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/render_pack_persistent.py` | repo      | Persistent fish-speech process wrapper. Loads model once + processes N phrases sequentially. Used to build the 5 shipped packs. |
| `scripts/render_pack.py`            | repo      | Shell-out variant (per-phrase model load) — the slower fallback.                                                                |
| `docs/PACK_RENDERING.md`            | repo      | The full offline pipeline documented end-to-end.                                                                                |
| `~/fish-experiment/fish-speech`     | user disk | Fish-speech repo + venv + model weights, already installed and working on the user's box.                                       |

What we DON'T have:

- An HTTP server wrapping the persistent process (we shell out to it
  in batch today).
- Rust client glue.
- `voiceforge note` Rust CLI.
- Chunking / resume / progress / notify infrastructure.
- Fish-speech-aware clone recipe (current clone produces multi-aux-ref
  for GPT-SoVITS).

# PR A — Fish-speech S2 Pro live runtime

**~3 days. Owner: Python + Rust client glue.**

## Surface

- **NEW** `services/tts-server-fish/server.py` — Flask (or FastAPI)
  HTTP server wrapping the persistent fish-speech process.
  - `POST /tts` `{text, voice_ref_path, voice_ref_text, sample_rate?}` → WAV bytes
  - `GET /health` → `{status, model_loaded, uptime_seconds}`
  - `GET /info` → `{engine: "fish-speech-s2-pro", version, sample_rate, max_chars}`
  - Long-lived process; model loads at startup (~30-60s); subsequent
    requests reuse loaded state.
  - Concurrent requests serialized internally (the model is not

  - HTTP POST to `http://127.0.0.1:5556/tts`, write WAV to
    `~/.voiceforge/cache/<sha>.wav`, return path.
  - Cache key includes engine name so fish-speech and GPT-SoVITS
    outputs don't collide.
  - 5-minute per-request timeout (fish-speech is slow on long input).

# PR B — Fish-speech-compatible clone recipe

**~3 days. Owner: bash + Rust + voice profile schema.**

## What changes

Today `voiceforge clone` runs the multi-aux-ref pipeline:
1 main reference (10s) + 5 auxiliary references (10s each), all
Whisper-transcribed, packaged for GPT-SoVITS. Output:
`~/.voiceforge/voices/<name>/{ref_main.wav, aux_1..5.wav, profile.toml}`.

Fish-speech S2 Pro wants a different reference shape:

- One clean reference clip, ideally ~10-15s, mono 22050 Hz
- One reference text (transcript of the clip)
- That's it. No multi-aux fusion.

## Surface

- **NEW** `scripts/clone_voice_fish.sh` — adapts the existing
  `clone_voice.sh` recipe:
  1. Take downloaded source WAV (yt-dlp + ffmpeg ingest, unchanged)
  2. Pick the cleanest 10-15s segment via VAD or simple energy-RMS
     analysis (deferred: simplest first cut takes a fixed offset)
  3. Whisper-transcribe just that segment
  4. Write `~/.voiceforge/voices/<name>/{ref.wav, ref.txt, profile.toml}`

- **MODIFIED** `apps/voiceforge-cli/src/voices.rs`:
  - `pub const VOICE_SCHEMA_VERSION: u32 = 2;` (bump from 1)
  - `pub struct VoiceProfile` gains `recipe: String` (now `"fish-speech-s2-pro"`
    or `"gpt-sovits-v2-multi-aux-ref"`)
  - `load_voice` accepts both schemas during deprecation window;
    warns on schema 1 voices that "this voice was cloned for the
    legacy GPT-SoVITS engine; re-clone for studio quality."
  - `pub fn voice_engine(profile: &VoiceProfile) -> &str` returns
    the recipe used, so the dispatcher can pick the right engine
    per-voice.

- **MODIFIED** `apps/voiceforge-cli/src/clone.rs`:
  - Default recipe is now fish-speech.
  - `--legacy-gpt-sovits` flag opts back into the old recipe.

- **MODIFIED** `apps/voiceforge-cli/src/doctor.rs`:
  - For each cloned voice, report which engine's recipe it was
    built with. Warns on schema-1 voices.

- **NEW** `apps/voiceforge-cli/src/migrate_voices.rs` (small):
  - `voiceforge voices migrate <name>` re-runs the fish-speech recipe
    on the original source clip if still present.
  - Doctor row links to this when it sees schema-1 voices.

# PR C — `voiceforge note` CLI

**~4 days. Owner: Rust CLI + chunking + resume + progress + notify.**

The launch headline. Everything funnels into one user command.

## CLI shape

```bash
voiceforge note \
  --voice tyson \                     # required: cloned voice name
  --in book.txt \                     # required: input file (txt | md)
  --out narration.wav \               # required: output file (or directory if --per-chapter)
  --chunk-by paragraph \              # optional: paragraph (default) | sentence
  --max-chunk-chars 800 \             # optional: split paragraphs longer than N
  --per-chapter \                     # optional: emit one WAV per detected chapter
  --progress \                        # optional: live progress bar to stdout
  --notify-on-done \                  # optional: macOS notification when finished
  --resume \                          # optional: pick up from last completed chunk
  --format wav                        # optional: wav (default) | mp3 | m4b
```

Input is auto-detected by extension:

- `.txt`, `.md` → text passthrough (markdown headings → chapter markers)
- `.pdf` → text extracted via `pdftotext` (poppler-utils) or `pdf-extract` Rust crate; layout heuristics detect chapters
- `.epub` → `pandoc` shell-out or dedicated crate (deferred to v0.4.1 if scope-bloated)
- stdin (no `--in`) → treated as text

`--per-chapter` only meaningful for inputs that have detectable chapters
(headings in MD/PDF, `Chapter N` patterns). For flat input, defaults to
single-output regardless of flag (with a warn).

Stdin variants:

```bash
cat book.md | voiceforge note --voice tyson --out book.wav
echo "Hello world" | voiceforge note --voice tyson --out hi.wav
```

## State + resumability

Per-job state directory next to the output WAV:

```
narration.wav.partial/
├── job.json               # {voice, input_sha256, total_chunks, started_at, engine}
├── chunks/
│   ├── 0001.wav           # synthesized chunk 1
│   ├── 0002.wav           # synthesized chunk 2
│   └── ...
└── progress.json          # {done: 47, total: 200, eta_seconds: 3600, current_text: "..."}
```

On `--resume`:

1. Load `job.json`, verify input file SHA matches (no resuming a
   different document)
2. Count `chunks/*.wav` to determine `done`
3. Skip the first `done` chunks; synth the rest
4. Concat all chunks via ffmpeg; clean up `.partial/` on success

## Progress + notify

Progress bar uses `indicatif` (Rust crate, already common in CLI tools).
Format:

```
voiceforge note: chunk 47/200 [████████░░░░░░░░░░░] 23%  ETA 1h 12m
                 current: "...the universe doesn't whisper its discoveries..."
```

Notify-on-done leverages **3.5's `notify_macos::Mirror`** infrastructure
already shipped. New helper:

```rust
notify_macos::send(title: &str, body: &str)  // fire-and-forget
```

Used: `send("voiceforge", "Tyson finished narrating book.txt (32 min)")`.

## Format conversion

WAV is the lossless intermediate. `--format mp3` and `--format m4b`
shell out to ffmpeg with appropriate flags. m4b is the audiobook
container — chapter markers from `# heading` lines in markdown input
(stretch goal; v0.4.1 if not in scope).

# Migration strategy

Existing GPT-SoVITS-cloned voices (the user has 3: peter-clean,
peter-nike-only, peter-nike32) keep working but are flagged.

1. **Doctor row** lists each schema-1 voice with: "cloned for legacy
   GPT-SoVITS engine; run `voiceforge voices migrate <name>` for
   studio quality."

2. **Auto-route at synth time**: if a cloned voice has
   `recipe = "gpt-sovits-v2-multi-aux-ref"`, dispatcher routes to the
   GPT-SoVITS server even if `VOICEFORGE_TTS_ENGINE` is fish-speech.
   No silent quality drop.

3. **`voiceforge voices migrate <name>`** re-runs the fish-speech
   recipe if the original source clip is still on disk. If not, asks
   the user to re-run `voiceforge clone <name> <source>` themselves.

4. **v0.5 deletes GPT-SoVITS** entirely. By then most users will
   have migrated. Last-call deprecation warning fires loudly in v0.4
   patch releases.

# Risks + edge cases

| #   | Risk                                                          | Mitigation                                                                                                                        |
| --- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Fish-speech model load is ~30-60s; first request feels broken | Doctor says "fish-speech model loaded ✓" only after warm-up; daemon command auto-starts the Python server if it can find the venv |
| 2   | Concurrent synth crashes the model                            | Server serializes internally with a `threading.Lock` or `asyncio.Semaphore(1)`                                                    |
| 3   | Long input (10k+ words) OOMs the model                        | Chunking is mandatory in `voiceforge note`; max chunk size enforced                                                               |
| 4   | User runs `voiceforge note` overnight and the laptop sleeps   | Detect via `pmset` query at startup; warn + suggest `caffeinate -i voiceforge note ...`                                           |
| 5   | User points `--in` at a binary file                           | MIME detect; reject anything that's not text/markdown                                                                             |
| 6   | Output file already exists                                    | Refuse without `--force`; matches existing pattern                                                                                |
| 7   | Resume after input file was edited                            | input_sha256 in job.json catches it; refuses to resume, suggests starting fresh                                                   |
| 8   | Disk fills mid-batch                                          | Pre-flight check estimates needed bytes (chunks × ~200 KB / chunk avg); refuses if free < needed × 1.5                            |
| 9   | User Ctrl-C mid-batch                                         | `.partial/` survives; `--resume` picks up. Tested in property-based test                                                          |
| 10  | Fish-speech HTTP server dies mid-batch                        | Per-chunk retry (3×) with exponential backoff; if persistent, fail with helpful message + state preserved for resume              |
| 11  | macOS notifications denied                                    | Notify silently no-ops; doctor warns at startup                                                                                   |
| 12  | User on Linux with no fish-speech installation                | Doctor explicitly tells them: "fish-speech requires CUDA + linux-x86_64 manual setup; see docs/INSTALL_FISH_SPEECH.md"            |

# Pipeline accuracy invariants (the "PIPELINE NEEDS TO BE ACCURATE" gate)

User has explicitly demanded: **build it right, write ample tests,
PIPELINE NEEDS TO BE ACCURATE.** These are the testable invariants the
note-pipeline MUST satisfy. Any PR-C merge that violates them is a
showstopper.

| # | Invariant | Test |
|---|-----------|------|
| I1 | **Lossless chunking.** Re-joining all chunks (in order, with single-space separator) reconstructs the input modulo whitespace normalization. No silent text drops. | `proptest!`: arbitrary input → chunk → join == input.normalize_ws() |
| I2 | **Order preservation.** chunk_N.wav corresponds to text chunk N for all N. No reordering. | Synth N chunks with deterministic synthetic content; ffprobe each output WAV; assert sequence matches input order |
| I3 | **Concat correctness.** Final output WAV duration == sum of chunk durations ± 100ms tolerance for ffmpeg sample-boundary fudge. | ffprobe each chunk's duration; ffprobe final output; assert |Σchunks − final| < 0.1s |
| I4 | **Resume idempotence.** For input I, running synth-to-completion produces output O1. Killing the run at any chunk K and resuming produces output O2. Assert sha256(O1) == sha256(O2). | Property test: spawn note → SIGTERM at random chunk → resume → diff sha |
| I5 | **Input-change detection on resume.** Resume against a modified input must refuse + warn (no silent corruption from mismatched state). | Edit input file mid-run; `--resume` must bail with "input changed (sha mismatch)" |
| I6 | **No silent chunk loss on engine error.** If chunk K fails synth after retries, the partial state preserves chunks 1..K-1 AND a `failed.json` records {failed_at, chunk_text, error}. Resume after fixing the underlying issue picks up at K. | Mock the synth client to fail chunk 5 with a network error; assert state preserved + `failed.json` written + resume completes |
| I7 | **Per-chapter mode preserves chapter text exactly.** chapter-N.wav for chapter N contains synthesis of EXACTLY that chapter's text — no bleed from N±1. | Stage a 3-chapter input; synth `--per-chapter`; transcribe each output via Whisper; assert text similarity > 0.95 with the source chapter (allowing for TTS phonetic variance) |
| I8 | **Cache key correctness.** A given `(text, voice, engine)` triple produces a deterministic cache filename. Re-running the same chunk must hit the cache, not re-synth. | Hash cache key computation in unit tests; integration test asserts second run is ~instant |
| I9 | **No cross-voice contamination.** Synthesizing the same text under voice A and voice B writes to different cache paths and audibly differs. | Cache key includes voice name; integration test asserts the two output files differ in sha256 AND in MFCC similarity (both = "different voice") |

## Architectural corrections (S1-S6 fold)

### A1. Fish-speech runtime is **NDJSON over stdio**, not HTTP

Mirrors the existing `CloningEngine` (`apps/voiceforge-cli/src/tts.rs:341-523`)
pattern exactly:

- `apps/voiceforge-cli/src/tts_fish.rs` (new): `pub struct FishEngine`
  owns a long-lived `tokio::process::Child` running
  `scripts/fish_speech_synth.py` over stdin/stdout
- Request: one JSON line `{text, voice_ref_path, voice_ref_text, seed}`
- Response: one JSON line `{ok, wav_path, error}` — wav written to
  `~/.voiceforge/cache/<sha>.wav`, path returned (NOT bytes — same
  shared-filesystem assumption CloningEngine already uses)
- Supervision: `kill_on_drop(true)` so engine drop cleans up
- Model load happens once at child spawn (~30-60s); subsequent requests reuse
- **No HTTP server, no port, no firewall surface.** Faster than HTTP
  (no localhost socket round-trip, no JSON-encoded WAV body).

Rejected option: HTTP at port 5556. The "share process across daemon
+ note" concern is real — solved by `voiceforge daemon` owning the
single fish-speech child + serving `voiceforge note` over the existing
1.8 NDJSON Unix socket. Single supervision tree.

**Consequence for plan v1/v2:** every "tts-server-fish HTTP server"
mention is a structural error. Replaced by stdio child. Doctor probes
the child's stdio, not a port. No `port_available` checks.

### A5. Pipeline invariants — I4 rewrite + I11/I12/I13 added

I4 (REVISED — was bit-identical, now chunk-cache):
> **Resume cache idempotence.** For input I, killed at chunk K, the
> resumed run reads chunks/0001..chunks/K-1.wav byte-for-byte (sha256
> equal to no-interruption baseline) and only re-synthesizes chunks
> K..N. The final concatenated output is NOT required to be
> bit-identical to the no-interruption run — fish-speech is a
> stochastic decoder. The invariant is "no work is wasted, no chunks
> are re-synthesized unnecessarily."

I11 (NEW — atomicity):
> **Chunk write atomicity.** Killing the process mid-chunk-write must
> not leave a corrupt WAV in `chunks/`. Either the chunk file is
> fully written + RIFF-valid + sha256-recorded in `progress.json`,
> or it doesn't exist (or has a `.tmp` suffix that resume ignores).
> Tested via SIGINT-at-write integration test.

I12 (NEW — concat ordering):
> **Concat ordering under filename collation.** ffmpeg concat reads
> from an explicit list file built from sorted chunk filenames using
> zero-padded indices (0001, 0002, ..., 9999). Glob-based concat is
> forbidden — `*.wav` would sort `10.wav` before `9.wav` and corrupt
> the audio order. Test asserts the list file is built from numeric
> sort, not lexicographic glob.

I13 (NEW — cross-profile cache invalidation):
> **Voice cache cross-profile invalidation.** The cache key for a
> synthesized chunk includes the voice profile's recipe field
> explicitly (`"fish-speech-s2-pro"` or `"gpt-sovits-v2-multi-aux-ref"`).
> Re-cloning voice X (different recipe OR different `created_at`)
> generates new cache entries; old entries become orphans (cleaned
> by `voiceforge cache prune`).

### A6. Pre-flight disk space check (S6 fold)

```rust
pub fn preflight_disk_space(path: &Path, needed_bytes: u64) -> Result<()> {
    let stat = nix::sys::statvfs::statvfs(path)?;
    let available = stat.blocks_available() as u64 * stat.fragment_size() as u64;
    let needed_with_headroom = needed_bytes.saturating_mul(15) / 10;  // 1.5x
    if available < needed_with_headroom {
        bail!(
            "insufficient disk: need ~{} GB free, have {} GB.\n\
             Free up space and re-run: voiceforge install-cloning",
            needed_with_headroom / 1_000_000_000,
            available / 1_000_000_000
        );
    }
    Ok(())
}
```

## SS2 fix: drop HTTP-isms (B7 + M7); restate as stdio semantics

Both `B7` and `M7` from v3 used HTTP terminology (503, Retry-After) that
makes no sense for stdio. Stdio analogs:

**Backpressure (was B7):** `FishEngine` holds a `tokio::sync::Semaphore(1)`.
`speak()` awaits the permit before sending the NDJSON request. No 503,
no Retry-After — caller just awaits naturally. fish-speech model is
single-threaded; serializing at the engine is the whole point.

**Warmup (was M7):** `FishEngine::spawn_child()` reads stdout until it
sees `{"ok": true, "ready": true}` before returning the constructed
engine. `speak()` calls cannot race warmup because `spawn_child()` is
`await`ed before any `speak()` permit can resolve. Test:
`fish_engine_spawn_child_blocks_until_ready_line_received`.

Mirrors `CloningEngine::spawn_child` at `tts.rs:496-520`.

## B-v3-5 fix: SHA-256 per chunk in I11 makes I4 verifiable

I11 (REVISED):
> **Chunk write atomicity + integrity.** Killing the process mid-write
> must not leave a corrupt WAV in `chunks/`. Each successfully written

> the mismatching index).

~5-30 sec synth.

> on disk matches `progress.json[chunk_index].sha256` AND matches the
