## Goal

After `voiceforge install-cloning` (v2 fish-speech path) completes the bash
installer, prove the synth pipeline actually works end-to-end before claiming
success. A torn install where pip succeeded but text2semantic weights are
corrupted must fail loud, not silently produce a "ready" doctor row that
wastes the user's first clone attempt 30 seconds later.

## Design (v2 — folds rust-expert MAJOR-REVISE)

### Architectural decisions (4 forced by review pass 1)

1. **Audio fixture is real human speech, NOT generated.** The v1 plan said
   "generated sine sweep is sufficient." That's a false-positive trap: a
   torn install where text2semantic weights are corrupt will gladly encode
   a sweep prompt to garbage tokens, autoregressive over them, and emit a
   valid 8-second WAV of pink noise. RIFF + WAVE + size threshold all pass.
   Use a real ~8s clip generated locally via macOS `say` (deterministic
   across builds, real speech for DAC encoder, ~250-500 KB committed).
2. **Smoke voice lives at `~/.voiceforge/cloning/.smoke/`, NOT under voices/.**
   Hidden from `voiceforge voices list`, can't tab-complete on `voiceforge
clone`, doesn't mix into the `KNOWN_RECIPES` schema, can't get cached
   by any user-facing path resolver.
3. **`FishEngine` gains `speak_with_explicit_ref()` that bypasses
   `voices::load_voice`.** The hidden smoke voice doesn't have a v1
   gpt-sovits-v2-multi-aux-ref profile and never will. Plumbing an explicit
   `ref_wav` + `ref_txt` path through the NDJSON request is ~30 LoC across
   FishEngine, fish_speech_synth.py, and one new test.
4. **Smoke result stored in standalone `~/.voiceforge/cloning/SMOKE.toml`,
   NOT bumped into INSTALLED.toml.** No race with the bash installer's
   atomic marker write. No schema-version bump. No migration. Doctor reads
   both files independently.

### Async-shape forced by review S2

`install_cloning::run()` flips from `fn` to `async fn`. Caller in
`main.rs::556-567` already runs inside `#[tokio::main]`, so the change is
adding `.await`. Two test files call `run()` (`install_cloning::tests::run_rejects_conflicting_flags`,
maybe others) — all need `#[tokio::test]` annotation.

### Wizard-integration forced by review R1

Smoke is the LAST WIZARD PHASE, not post-teardown. After bash exit success:

- `install_ui::run_with_wizard` returns the bash status
- The wizard's `MultiProgress` is NOT torn down yet
- A new `MultiProgress::add(ProgressBar::new_spinner())` line is added for
  the smoke phase with a 5s tick interval
- Inside that spinner's lifetime, `install_smoke::run_smoke_test().await`
  runs (~30-90s on CPU)
- Spinner finishes/abandons based on result, then wizard tears down

This means `install_smoke::run_smoke_test` returns a result the wizard
consumes; the wizard renders the success/failure message itself. Cleaner
than the v1 "smoke prints its own banner" design.

#### 3. `apps/voiceforge-cli/src/install_smoke.rs` (~280 LoC)

**N2 fix (rust-expert pass-2):** the smoke orchestrator must accept a

```rust
/// Object-safe synth contract for the smoke orchestrator. FishEngine
/// is the prod impl; tests inject a MockSynth that writes a known WAV
/// without spawning a python child.
#[async_trait::async_trait]
pub trait SmokeSynth: Send + Sync {
    async fn speak_with_explicit_ref(
        &self,
        text: &str,
        ref_wav: &Path,
        ref_txt: &str,
        out: &Path,
    ) -> Result<()>;
}

#[async_trait::async_trait]
impl SmokeSynth for crate::tts::FishEngine {
    async fn speak_with_explicit_ref(
        &self,
        text: &str,
        ref_wav: &Path,
        ref_txt: &str,
        out: &Path,
    ) -> Result<()> {
        FishEngine::speak_with_explicit_ref(self, text, ref_wav, ref_txt, out).await
    }
}

pub struct SmokeResult {
    pub passed: bool,
    pub duration_ms: u64,
    pub wav_bytes: u64,
    pub sample_count: usize,
    pub message: String,
}

/// Prod entry point: constructs FishEngine + delegates to the trait
/// version. Bails if the v2 marker is absent (install broken upstream).
pub async fn run_smoke_test() -> Result<SmokeResult> {
    let engine = crate::tts::FishEngine::new()?;
    run_smoke_test_with(&engine).await
}

/// Test-friendly entry point. Mock-python integration tests pre-seed
/// a fake schema-2 marker via `install_cloning::tests::with_home(...)`
/// + `write_v2_marker(...)`, then call this with a `MockSynth`. The
/// FishEngine::new() path is bypassed entirely.
pub async fn run_smoke_test_with<S: SmokeSynth + ?Sized>(synth: &S) -> Result<SmokeResult>
```

Flow:

1. Resolve `~/.voiceforge/cloning/.smoke/` and create it.
2. Extract embedded smoke fixture (`embedded_install::extract_all` already
   does this; reuse the path).
3. (Prod-only — `run_smoke_test`) Construct `FishEngine::new()`. Bail-up
   if it fails (means schema-2 marker missing — install is broken
   upstream). Test path skips this; caller injects the synth.
4. Drop guard set up: `SmokeCleanup` impl that `remove_dir_all(.smoke/)`s
   on drop. NOT a `defer` macro, a real Drop impl.
5. Call `synth.speak_with_explicit_ref("the quick brown fox jumps over
the lazy dog", &ref_wav, &ref_txt, &out_path)`.
6. Verify output WAV:
   - File exists
   - First 4 bytes are `"RIFF"`
   - Bytes 8-12 are `"WAVE"`
   - Total file size ≥ 100_000 (3-second utterance @ 32kHz mono PCM_16
     ≈ 190 KB; 100KB floor catches "0-second WAV header only" failures)
   - `hound::WavReader::open(out).into_samples::<i16>().count() > 0`
     (M5 defense — catches "valid header, zero samples")
7. Drop guard runs `remove_dir_all` automatically on return.
8. Also remove the cached output WAV at `cache_path_for(...)`. The
   FishEngine cache key includes the ref_wav path now (per #2 design),
   so the smoke output is at a deterministic cache path.
9. Return `SmokeResult` with `passed=true` + timing/size data.

On fish-speech-side failure (Err from `speak_with_explicit_ref`), return
`SmokeResult { passed: false, message: <err.to_string()>, .. }`. Don't
bubble the Err — the orchestrator wants to record the failure and surface
it, not propagate.

#### 5. Wire into `install_cloning::run()`

```rust
pub async fn run(force: bool, check: bool, uninstall: bool) -> Result<()> {
    // ... existing setup ...

    let bash_status = if use_wizard {
        // wizard runs WITHOUT tearing down; returns the MultiProgress + status
        let (mp, status) = install_ui::run_with_wizard_keep_alive(...)?;
        if status.success() && engine == InstallEngine::FishSpeechS2Pro &&

                .ok().is_some_and(|v| !v.is_empty()) {

        }

        cmd.status()?
    };

    // ... existing post-status handling ...
}
```

**N1 fix (rust-expert pass-2): pin the `run_with_wizard_keep_alive`
contract so the implementer doesn't have to re-derive it.** The naive
"return (MP, ExitStatus)" shape has three sub-issues the v2 plan
hand-waved over. Specification:

1. **Return shape is asymmetric:**

   ```rust
   pub fn run_with_wizard_keep_alive(
       cmd: &mut Command,
       total_phases: usize,
       title: &str,
   ) -> Result<WizardOutcome>;

   pub enum WizardOutcome {
       /// Bash exited successfully. MultiProgress is alive, header bar
       /// is finished_with_message("done") but VISIBLE, phase_bar is
       /// finished_and_clear()'d (gone). Caller may add a fresh
       /// spinner via `add_smoke_phase(&mp)` for the smoke phase.
       Success { mp: MultiProgress },
       /// Bash exited non-zero. Bars are already abandoned and the
       /// captured-stdout last-80-lines dump has been written to
       /// stderr internally — caller never sees a "MultiProgress with
       /// garbage on it" state. Caller bails up with the status.
       Failed { status: ExitStatus },
   }
   ```

2. **Bar lifecycle (internal to `run_with_wizard_keep_alive`):**
   - Success: `header.finish_with_message("done")` (visible, "done"),
     `phase_bar.finish_and_clear()` (gone). Then return.
   - Failure: `header.abandon_with_message("FAILED")`,
     `phase_bar.abandon()`, dump captured stdout to stderr (existing
     behavior at install_ui.rs:131-146), then return.

3. **Why the smoke phase MUST be added BEFORE the header is finished:**
   indicatif renders bars in `MultiProgress::add` order, top to bottom.
   If the caller adds the smoke spinner AFTER `finish_with_message`
   prints "done", the spinner appears below a "done" header, which
   reads as broken. Either: (a) `add_smoke_phase` finishes the existing
   header _first_ and re-renders, or (b) the caller adds the smoke
   phase between bash-exit-success and header-finish. Pick (a) — it
   keeps the API surface small and the wizard owns its own bars.

   Concretely, `add_smoke_phase` does: `header.finish_with_message("done");
mp.add(ProgressBar::new_spinner())`. Returns the new spinner handle.

4. **`finish_smoke_phase(handle, &result)` flips it to ✓/✗ and sets
   the message.** On success: `handle.finish_with_message(format!("✓ smoke
passed in {ms}ms"))`. On failure:
   `handle.abandon_with_message(format!("✗ smoke failed: {}", result.message))`.

Refactor blast radius (low): only one prod caller of `run_with_wizard`
(`install_cloning::run`) and one test
(`run_with_wizard_drives_phases_from_script` in install_ui::tests).
Both updated as part of commit 6d-6.

### `cargo test` safety net (M6)

Every smoke test that could potentially spawn fish-speech wraps with
`with_home(tmp.path(), ...)` per the existing pattern in
`install_cloning::tests`. The mock-python tests use a temp script.
The real-e2e tests are gated behind the env var and have a top-of-file
`#[ignore]` attribute as a belt-and-suspenders.

`cargo test` on a clean checkout (no env vars) MUST never spawn the
real `~/.voiceforge/cloning/venv/bin/python` even if a real install
exists on the dev's machine. Verify by running the suite on the dev
box where fish-speech IS installed and confirming no python child
appears in `ps aux | grep fish_speech_synth`.

### Risks

#### R1 (carryover from v1, downgraded): hound deterministic-bytes claim moot

We're not generating audio at build time anymore (per #1, we commit the
fixture bytes directly). The v1 risk goes away.

#### R2 (carryover, addressed): rolls_back rename

#### R3 (new): say-generated audio determinism across dev boxes

Different macOS versions ship different `say` voices. Different ffmpeg
versions produce different loudnorm output. The committed bytes are what
ship in the binary; the regenerate-the-fixture script is documented but
not run in CI. If a dev re-runs the regenerate script and commits new
bytes, the embedded constant changes — that's caught by the
`SMOKE_REFERENCE_WAV` SHA256 assertion in the existing
`embedded_constants_meet_minimum_size_thresholds` test (extend it to also
assert SHA256 once the canonical fixture is generated and locked).

#### R4 (new): wizard `MultiProgress` keep-alive refactor blast radius

Changing `run_with_wizard` to return `(MultiProgress, ExitStatus)` breaks
the existing call site in `install_cloning::run` (only one caller — easy)
and the existing test `run_with_wizard_drives_phases_from_script` in
`install_ui` (needs to consume the new return shape — simple update).
No external consumers since `install_ui` is a binary crate's internal
module. Low blast radius.
