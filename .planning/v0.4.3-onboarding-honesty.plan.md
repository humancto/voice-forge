# v0.4.3 — onboarding honesty (docs only)

## Goal

Close the worst first-time-user gaps in README.md + docs/index.html. No
Rust changes, no script changes — just bring the user-facing copy in
line with what v0.4.2 actually ships.

## Why

A new user clicking through from a launch link today sees:

- **Install size off by ~7×**: README claims `~1.7 GB` for
  `voiceforge install-cloning` (a number left over from v1 GPT-SoVITS).
  Reality: fish-speech S2 Pro weights alone are ~10 GB; cold install is
  ~12 GB. Anyone with a metered connection rage-quits before step 4.
- **Synth speed off by ~10-60×**: README claims `~2-3 s synth on CPU`
  and `~3 s synth on CPU` (warm). Reality on an M2: ~62 s of CPU synth
  per 1 s of audio (1/62× realtime), ~20 s/1 s on the new MPS default
  (1/20× realtime). The claim was true for XTTS, not fish-speech.
- **v0.4.2's MPS default + `VOICEFORGE_FISH_SYNTH_DEVICE` override are
  invisible** in user docs. The 3× speedup we just shipped is unbilled.
- **The headline use case ("point at audio, get audio notes in cloned
  voice") has no documented end-to-end recipe.** Whisper IS installed
  by `install-cloning` (at `~/.voiceforge/cloning/venv/bin/whisper`)
  but never surfaced. Users have to invent the chain themselves.
- **Prereqs callout missing**: macOS arm64 only today, ~12 GB free
  disk, M-series strongly recommended, `brew install yt-dlp` separately
  for URL ingest. Currently spread across §5, Step 2, "Sourcing audio".

Stale numbers caught in the v0.4.2 review-and-ship loop. Memory
`decisions-voice-forge` has the measured realtime ratios from today's
M2 + Tyson-clone test.

## Scope

README.md + docs/index.html only. No code, no scripts, no Cargo.toml.

   implication that `say` is instant after install.

3. **README:361** — replace `~10 min, ~1.7 GB` with
   `~20-60 min depending on connection, ~12 GB` in the prose Step 2.

4. **README:382** — replace `subsequent reactions in the same process
are warm (~3 s synth on CPU)` with `subsequent reactions in the
same process are warm — short phrases take ~1 min on MPS, ~3 min
on CPU. For long-form (voiceforge note), see Speed Expectations
below.` Stops implying interactive throughput where there is none.

5. **README:501** — table cell still says `GPT-SoVITS v2`. Replace

6. **NEW: Prereqs callout** above Quick Start §1 (before line 340).
   Compact `> Note:` block listing:
   - macOS arm64 only today (Linux roadmapped, not shipped)
   - ~12 GB free disk for the cloning install
   - M-series strongly recommended (M1/M2/M3) — MPS is the new default
   - `brew install yt-dlp` separately for URL ingest

     dominated by your link speed)

7. **NEW: §5.5 "Source audio → audio notes in a cloned voice"** —
   insert between §5 (Clone) and §6 (Pipe NDJSON). Shows the missing
   end-to-end chain in copy-pasteable shell.

   Editorial review pass 1 caught two real defects in the original
   draft: yt-dlp's `-x --audio-format wav` produces stereo at source
   rate (44.1/48 kHz) which whisper has to resample, and the
   `whisper ... > source.txt` redirect captures the progress log, NOT
   the transcript — whisper writes `<basename>.txt` next to the input
   regardless. Corrected chain:

   ```bash
   # 1. Pull source audio (mono 16 kHz — matches what whisper expects)
   yt-dlp -x --audio-format wav \
     --postprocessor-args "-ac 1 -ar 16000" \
     -o source.wav "<URL>"

   # 2. (Optional) clip the first 5 minutes — full-length sources can
   #    push the next step into overnight territory. See §10 below.
   ffmpeg -i source.wav -t 300 source_clip.wav

   # 3. Transcribe with the bundled whisper (installed by install-cloning).
   #    --output_dir places source_clip.txt next to the input; the CLI
   #    does NOT write the transcript to stdout, so don't redirect.
   ~/.voiceforge/cloning/venv/bin/whisper source_clip.wav \
     --model medium --output_format txt --output_dir .

   # 4. Clone the voice you want to narrate IN (separate audio file ≥60s)
   voiceforge clone narrator ./narrator_60s.wav

   # 5. Narrate the transcript in that voice
   voiceforge note --voice narrator --in source_clip.txt --out narrated.wav
   ```

   Caveat box: this is a manual chain today. Step 5 is overnight-class
   for 30-minute source audio (see Speed Expectations below); sweet
   spot is 1-5 minute clips. A one-command `voiceforge audiobook`
   wrapper is planned for v0.5.

8. **NEW: §10 "Speed expectations"** — new section after "How it works",
   before "What's new since v0.2.0". Compact realtime-ratio table:

   | Use case                        | Output length | MPS wall-clock | CPU wall-clock |
   | ------------------------------- | ------------- | -------------- | -------------- |
   | `voiceforge say` short reaction | 1-3 s         | ~20-60 s       | ~1-3 min       |
   | 1-minute voice note             | 60 s          | ~20 min        | ~1 h           |
   | 5-minute summary                | 5 min         | ~1 h 40 min    | ~5 h           |
   | 30-minute chapter               | 30 min        | ~10 h          | ~30 h          |

   Two-line context: MPS is the default on Apple Silicon as of v0.4.2;
   set `VOICEFORGE_FISH_SYNTH_DEVICE=cpu` to force CPU (use on
   memory-constrained 16 GB M-series machines if MPS swaps).

9. **docs/index.html mirror updates** — the landing-page mirror of any
   README claim that changed. If a number appears in both files, both
   move together. Audit pass after the README diff is final; expect
   ~3-5 hunks in the HTML.
