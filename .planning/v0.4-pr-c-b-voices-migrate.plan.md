# PR-C-b: `voiceforge voices migrate <name>`

**Branch**: `feat/v0.4-pr-c-b-voices-migrate` off main (`718d37d`).
**Sprint**: v0.4 (post PR-C-a #45).
**Plan version**: v2 (folds 10 rust-expert REVISE items from pass-1).

## Goal

Convert an existing v1 voice profile (`schema=1`,
`recipe=gpt-sovits-v2-multi-aux-ref`) to v2 (`schema=2`,
`recipe=fish-speech-s2-pro`) in place. Atomic via sibling staging dir.
Idempotent on already-v2. Refuses on broken state with clear,
actionable errors. Leaves a recoverable `.v1.bak/` child so the original
aux files can be retrieved.

After this lands, a v0.3 user with a `peter` voice in
`~/.voiceforge/voices/peter/` can run `voiceforge voices migrate peter`
and `voiceforge say --voice peter` will route through fish-speech S2
Pro without re-cloning.

## Non-goals

- No `voiceforge voices unmigrate` (v2 → v1). The `.v1.bak/` child is
  the recovery surface; restoring it manually is fine until v0.5.
- No batch-migrate (`--all`). One voice per invocation.
- No re-synth / re-transcribe. We reuse the existing v1 `ref_main.wav`
  - `ref_main.txt` as the v2 `ref.wav` + `ref.txt`. **Fish-speech
    compatibility of the v1 ref clip is asserted in tests (see R5
    below).**

## Disk-shape contract

**Before migrate** (`~/.voiceforge/voices/peter/`):

```
profile.toml          schema=1, recipe=gpt-sovits-v2-multi-aux-ref, aux_count=N
ref_main.wav
ref_main.txt
aux_1.wav .. aux_N.wav
aux_1.txt .. aux_N.txt
```

N is whatever `aux_count` says (5 by default from `clone_voice.sh:201`;
hand-edited profiles with smaller N must also work — see R4).

**After migrate**:

```
profile.toml          schema=2, recipe=fish-speech-s2-pro
ref.wav               (was ref_main.wav)
ref.txt               (was ref_main.txt)
.v1.bak/
    profile.toml      original schema-1 profile
    ref_main.wav      copy of original main reference
    ref_main.txt
    aux_1.wav .. aux_N.wav   (aux_count pairs from original profile)
    aux_1.txt .. aux_N.txt
```

Critical: `.v1.bak/` is a CHILD of `<voice>/` (locked architecture
decision #3). `load_voice` never walks subdirs. Regression test
`load_voice_v2_tolerates_dot_v1_bak_child_dir` already exists in main.

## Atomic-rename protocol (rewritten per rust-expert S1)

Three transient dir names live next to the live `peter/` dir under
`~/.voiceforge/voices/`:

- `peter/` — live voice dir.
- `peter.partial-migrate/` — staging dir being built.
- `peter.migrating-old/` — the old v1 dir set aside during the flip.

The protocol is: stage → flip → **verify-then-cleanup** (with
**rollback on verify failure**). All multi-file copies inside step 4–5
are scope-guarded: any error nukes the staging dir before propagating.

### Pre-flight (covers all crash-recovery cases)

Before doing anything else, enumerate the four possible disk states
under `voices/` for this voice name:

| `peter/` | `partial-migrate/` | `migrating-old/` | State name                                                                                  | Action                                                                                                                                                                                                                                                              |
| -------- | ------------------ | ---------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| present  | absent             | absent           | **Clean**                                                                                   | Normal flow                                                                                                                                                                                                                                                         |
| present  | absent             | present          | **Stranded-old**                                                                            | Crash after 6c failed mid-cleanup. With `--force`: nuke `migrating-old/`. Without `--force`: bail with hint.                                                                                                                                                        |
| present  | present            | absent           | **Stranded-stage**                                                                          | Crash before 6a. With `--force`: nuke `partial-migrate/`. Without `--force`: bail with hint.                                                                                                                                                                        |
| present  | present            | present          | **Compound-stranded**                                                                       | Mid-protocol crash. With `--force`: nuke both. Without `--force`: bail with hint.                                                                                                                                                                                   |
| absent   | present            | absent           | **Mid-flip 6a→6b** (no auto-heal because the symptom alone is ambiguous; require `--force`) | With `--force`: nuke `partial-migrate/`, `rename(migrating-old, peter)`. Without `--force`: bail with hint. **(rust-expert S1.2: only auto-heal when `partial-migrate/` is also on disk.)**                                                                         |
| absent   | absent             | present          | **Orphan-old after remove**                                                                 | The user `voiceforge voices remove`d an in-between state. **Never silently restore** — refuse with `--force` required. With `--force`: bail and ask user to manually rename if they want the v1 back (we will NOT silently resurrect a previously-removed voice).   |
| absent   | present            | present          | **Self-heal 6a→6b**                                                                         | The only state where auto-heal is safe: clearly mid-protocol, the v1 has been staged-aside, and a staging dir exists. Auto-roll-back: `remove_dir_all(partial-migrate)`, `rename(migrating-old, peter)`, then proceed with the normal flow. (rust-expert S1.2 fix.) |
| absent   | absent             | absent           | **Missing voice**                                                                           | Bail: `"voice <name> not found"`.                                                                                                                                                                                                                                   |

This table is implemented as an explicit `match` on a
`PreflightState` enum so it is unmissable in code review.

### Normal flow (from the Clean state)

1. `load_voice(name)?` — must return `VoiceProfile::V1`. On `V2`:
   set `MigrateReport::AlreadyMigrated`, return Ok (idempotent no-op
   exit 0). On `Err`: propagate (we don't try to "fix" broken voices).
2. **Pre-flip notice** (rust-expert Q3 partial): `eprintln!` naming
   the voice dir and the staging dir, so Ctrl-C between notice and
   any disk change leaves the user informed.
3. `mkdir(staging)` — `voices/peter.partial-migrate/`.
4. **Scope-guarded staging build** (rust-expert B3). A private helper
   `build_v2_staging(...)` does all of steps 4a–4f inside a single
   function whose `?` on any error triggers a `Drop` impl on a
   `StagingGuard` that nukes the staging dir. Pseudocode:

   ```rust
   struct StagingGuard<'a> { path: &'a Path, armed: bool }
   impl Drop for StagingGuard<'_> {
       fn drop(&mut self) {
           if self.armed { let _ = fs::remove_dir_all(self.path); }
       }
   }
   ```

   4a. Write `staging/profile.toml` with the v2 schema (recipe =
   `fish-speech-s2-pro`; preserve `name`, `source`, `created_at`,
   `duration_seconds` from the loaded V1).
   4b. `copy(peter/ref_main.wav, staging/ref.wav)`.
   4c. `copy(peter/ref_main.txt, staging/ref.txt)`.
   4d. `mkdir(staging/.v1.bak)`.
   4e. `copy(peter/profile.toml, staging/.v1.bak/profile.toml)`.
   `copy(peter/ref_main.wav, staging/.v1.bak/ref_main.wav)`.
   `copy(peter/ref_main.txt, staging/.v1.bak/ref_main.txt)`.
   4f. For `i in 1..=v1.aux_count`:
   `copy(peter/aux_{i}.wav, staging/.v1.bak/aux_{i}.wav)`,
   `copy(peter/aux_{i}.txt, staging/.v1.bak/aux_{i}.txt)`.
   4g. `guard.armed = false` — staging is committed, no more rollback
   in this function.

5. **Atomic flip (verify BEFORE old-dir cleanup, per rust-expert S1.1)**:
   - 5a. `rename("peter", "peter.migrating-old")`. POSIX rename of a
     directory when the target doesn't exist is atomic.
   - 5b. `rename("peter.partial-migrate", "peter")`. Same.
   - 5c. **`verify_after_flip("peter", &hook)?`** — load_voice the
     new live dir, assert V2, run any injected hook. On error:
     ROLLBACK before returning:
     - `rename("peter", "peter.partial-migrate")` (move broken v2
       staging back to staging name).
     - `rename("peter.migrating-old", "peter")` (restore v1 to live).
     - Bail with a message naming both dirs and pointing at
       `--force`.
   - 5d. `remove_dir_all("peter.migrating-old")` — only reached on
     verify success. If this fails, it's a tidiness issue, not a
     correctness issue: warn but return Ok with the report (matches
     `packs.rs:940-948` precedent).

The verify-before-cleanup ordering is what closes the "v2 dir is
broken and there's no v1 fallback" hole rust-expert called out (S1.1).

### Fault-injection seam (rust-expert R3)

`migrate_voice` is the public entry; it delegates to a private
`migrate_voice_inner(name, force, post_flip_hook)` that takes a
`Box<dyn Fn() -> Result<()>>` defaulting to `|| Ok(())` in the public
path. The hook fires inside `verify_after_flip` AFTER `load_voice`
succeeds and BEFORE `remove_dir_all(migrating-old)`. Tests inject a
hook that returns an error and assert the on-disk state is fully
rolled back to v1.

```rust
pub fn migrate_voice(name: &str, force: bool) -> Result<MigrateReport> {
    migrate_voice_inner(name, force, &|| Ok(()))
}

#[cfg(test)]
fn migrate_voice_test_hook(
    name: &str, force: bool, hook: &dyn Fn() -> Result<()>,
) -> Result<MigrateReport> {
    migrate_voice_inner(name, force, hook)
}

fn migrate_voice_inner(
    name: &str, force: bool, post_flip_hook: &dyn Fn() -> Result<()>,
) -> Result<MigrateReport> { ... }
```

/// Outcome of a migrate run. Enum, not a struct with Option<T> fields,
/// so the typestate is compiler-checked (rust-expert A1).
#[derive(Debug, Clone)]
#[must_use = "the migrate report names the .v1.bak path users need"]
pub enum MigrateReport {
    /// Voice was already v2; migrate was a no-op.
    AlreadyMigrated {
        voice_name: String,
        /// If a .v1.bak/ exists in the voice dir, surface its path

        /// files are.

    /// Voice was migrated v1 → v2.

        voice_name: String,
        original_recipe: String,
        new_recipe: String,
        v1_bak_path: PathBuf,
    },
}

/// interrupted run (see the preflight table in module docs).

### Test-fixture duplication policy (rust-expert R7)

The existing `write_full_profile` test fixture in `voices.rs::tests`
is `#[cfg(test)]`-only. For the e2e test under
`apps/voiceforge-cli/tests/`, **duplicate** the fixture rather than
exposing a `pub(crate) #[cfg(test)]` module. Reason: the fixture is
~20 lines of TOML + 13 `fs::write` calls; exposing it across the lib
boundary costs more in API surface than the duplication costs in
maintenance. State this explicitly so the implementer doesn't dither.

6. **`migrate_bails_on_partial_dir_without_force`** — pre-stage

8. **`migrate_self_heals_only_when_partial_and_old_both_present`**

9. **`migrate_self_heals_when_mid_flip_state_detected`**: pre-stage

12. **`migrate_with_aux_count_3_copies_three_aux_pairs`** (rust-expert

13. **`migrate_full_6a_6b_compound_stranded_with_force`** (rust-expert

14. **`migrate_verify_failure_rolls_back_to_v1`** (rust-expert R3,

## Resolved open questions (rust-expert pass-1)

## Rollback plan (post-merge)

If `voiceforge voices migrate peter` left a user in a wedged state:

```bash
cd ~/.voiceforge/voices/peter
# Restore v1 in place:
cp .v1.bak/profile.toml profile.toml
cp .v1.bak/ref_main.wav ref_main.wav
cp .v1.bak/ref_main.txt ref_main.txt
# (aux files are already not at top level for v2; copy from .v1.bak/ as needed)
for i in 1 2 3 4 5; do
  cp ".v1.bak/aux_${i}.wav" "aux_${i}.wav"
  cp ".v1.bak/aux_${i}.txt" "aux_${i}.txt"
done
rm -rf .v1.bak
```

A future `voiceforge voices unmigrate <name>` (v0.5) automates this.
The CLI success message points users at `.v1.bak/`.
