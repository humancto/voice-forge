# PR-C: fish-speech clone recipe + voice profile schema v2 (plan v2)

**Status**: revised, folds rust-expert REVISE pass-1
**Branch**: `feat/v0.4-pr-c-clone-recipe`
**Parent**: `5f3e423` on `main` (docs/v0.4 index refresh)

## Goal

Turn `voiceforge clone` into a working v0.4 entrypoint. After PR-AB +
6d, the install pipeline succeeds and the post-install smoke synth
proves fish-speech runs, but **no user-facing command actually creates
a clonable voice via fish-speech yet**. PR-AB's FishEngine has
`speak_with_explicit_ref` (smoke-only); the regular `FishEngine::speak`
path calls `voices::load_voice` which currently rejects any
non-`gpt-sovits-v2-multi-aux-ref` recipe. So the v0.4 marketing
("clone any voice from ~60s of audio") has no working code path.

## Scope split (rust-expert PR-C pass-1)

Plan v1 tried to land 5 commits + ~900 LoC in one PR including
the migrate command. Reviewer pushed to split:

- **PR-C-a (this PR)**: voice profile schema v2 + `voiceforge clone`
  through fish-speech + FishEngine speak via load_voice. ~550 LoC.
  Lands the working clone path.
- **PR-C-b (follow-up)**: `voiceforge voices migrate <name>` command.
  ~250 LoC. Lands after PR-C-a so the migrate command has a stable
  target schema to migrate INTO. Not on the critical path — users
  can `voices remove peter && clone peter <src>` for a fresh v2
  clone in the interim.

This plan covers **PR-C-a only**. Migrate command moves to a
dedicated plan + PR after this lands.

## Decisions locked (forced by REVISE pass-1 + 3 pass-2 nits)

These are settled. Re-litigating in pass-2 is wasted cycles.

1. **Dispatch on install markers, NOT env (S1 fix).** `clone::run`
   probes `is_installed_v2()` first; falls back to `is_installed()`
   (v1). If neither is present, bail. No reading of
   `VOICEFORGE_INSTALL_CLONING_ENGINE` or `VOICEFORGE_TTS_ENGINE`
   from the clone path. Reason: the original plan referenced
   `InstallEngine::Embedded` which does not exist — `InstallEngine`
   has only two variants. Conflated with `tts::EngineKind`. Cleanest
   fix is to remove env-reading from clone entirely.

2. **VoiceProfile is `enum { V1, V2 }`, does NOT derive Deserialize
   on the outer enum (S2 fix).** Each variant is a separate
   `#[derive(Deserialize)]` struct. `load_voice` peeks
   `schema_version`, then deserializes into the appropriate variant
   and constructs the enum value in-memory.

3. **`peek_schema_version` lives in voices.rs (B4 fix).** Copy the
   ~10-line helper from install_cloning.rs rather than extracting
   to a shared module. Two copies is acceptable for a 10-line
   utility; sharing infrastructure across `voices` and
   `install_cloning` is a v0.5 cleanup, not a v0.4 commitment.

4. **Sample rate is 32 kHz mono PCM_16 (R1 fix).** Matches the
   embedded smoke fixture (`embedded_install.rs::SMOKE_REFERENCE_WAV`)
   which already flows through `encode_audio` end-to-end. Don't
   re-derive this decision in 6 months.

5. **Reference window length: 8s floor, 20s cap, middle-trim
   `min(source-10s, 20s)` (R2 fix).** Source >30s gets middle-trimmed
   to 20s (skip first/last 5s, take a 20s contiguous window).
   Source 8-30s used as-is. Source <8s rejected with hint
   "ref clip must be at least 8 seconds; got Xs".

6. **Whisper-base, not medium (R2 fix).** v1 uses `whisper.load_model("base")`.
   No reason to upgrade for v2 unless we have evidence medium yields
   measurably better transcripts for 8-20s windows. Base is ~5×
   faster. Keep consistency.

7. **`voice_exists()` stays schema-agnostic (M3 lock).** Continues
   to check `profile.toml` presence only. `load_voice` enforces
   schema. No downstream change in this PR.

8. **Pack-collision check lifted into `clone::run` BEFORE the
   v1/v2 dispatch (R4 fix).** Currently at clone.rs:44; stays where
   it is structurally (top-level pre-flight), then `run` dispatches
   to `run_v1` or `run_v2`. Both branches inherit the collision
   guarantee.

9. **`scripts/clone_voice_fish.sh` (bash, not Rust).** Mirrors
   v1's `clone_voice.sh` pattern. Reuse the test infra
   (`tests/install_cloning_fish_script.rs` pattern) for phase-line
   contract assertions.

10. **`.v1.bak/` is a CHILD of the voice dir (pass-2 nit lock).**
    PR-C-b's migration moves aux files to
    `~/.voiceforge/voices/<name>/.v1.bak/` (child), NOT
    `~/.voiceforge/voices/<name>.v1.bak/` (sibling). Reasons:
    (a) `load_voice` only opens specific files (profile.toml,
    ref.wav, ref.txt) and never walks subdirectories — child dir
    is structurally invisible.
    (b) `list_cloned_voices` walks `voices/`, not voice subdirs;
    sibling `.v1.bak/` would need a skip-list entry at
    `voices.rs:202` (today the skip-list catches `.partial` /
    `.lock.d`). Child placement avoids that touch in C-1a.
    (c) `voiceforge voices remove <name>` (existing) does
    `rm -rf <voice_dir>` which cleans `.v1.bak/` automatically.

11. **`voice_exists` callers (3 sites) intentionally untouched
    (pass-2 nit S3 footnote).** Per Decision #7, `voice_exists`
    stays schema-agnostic. The 3 prod callers stay unchanged
    in this PR:
    - `tts.rs:267` (Engine::speak dispatcher)
    - `main.rs:1176, 1278` (clone collision check + remove cmd)
    - `packs.rs:819` (pack-install collision check)

12. **Intermediate-state contract for the C-1b → C-4 window
    (pass-2 nit commits doc).** Between commits C-1b (V2 enum
    variant lit up in voices.rs) and C-4 (FishEngine::speak
    swap to load*voice), `FishEngine::speak` still pattern-matches
    only on `VoiceProfile::V1(*)`(because C-1a only updated it
to handle V1; V2 unwrap lands in C-4). A user who lands
between those two commits and somehow has a v2 profile on
disk would see`FishEngine::speak` bail with "this caller
    expects V1 — V2 unwrap not yet wired" (or compile error if
    we use exhaustive match). **Intended intermediate state.**
    Bisecting between C-1b and C-4 will land in this state;
    just keep going to C-4. C-3 ships clone_v2 which CAN write
    a V2 profile, but C-4 is what makes the resulting profile
    speakable.

## Design

### 1. `voices.rs::VoiceProfile` schema-aware enum

```rust
pub const KNOWN_RECIPES_V1: &[&str] = &["gpt-sovits-v2-multi-aux-ref"];
pub const KNOWN_RECIPES_V2: &[&str] = &["fish-speech-s2-pro"];

/// Schema-discriminated voice profile. Built by `load_voice`; NOT
/// derived `Deserialize` — the outer enum is an in-memory tagged
/// value. Each variant is `Deserialize` independently and
/// `load_voice` peeks `schema_version` to pick the variant.
#[derive(Debug, Clone, PartialEq)]
pub enum VoiceProfile {
    V1(VoiceProfileV1),
    V2(VoiceProfileV2),
}

#[derive(Debug, Clone, Deserialize, PartialEq)]
pub struct VoiceProfileV1 { /* renamed from existing VoiceProfile */ }

#[derive(Debug, Clone, Deserialize, PartialEq)]
pub struct VoiceProfileV2 {
    pub schema_version: u32,       // == 2
    pub name: String,
    pub source: String,
    pub created_at: String,
    pub duration_seconds: f64,
    pub recipe: String,            // in KNOWN_RECIPES_V2
    #[serde(skip)] pub dir: PathBuf,
    #[serde(skip)] pub ref_wav: PathBuf,
    #[serde(skip)] pub ref_txt: PathBuf,
}

impl VoiceProfile {
    pub fn name(&self) -> &str { ... }
    pub fn source(&self) -> &str { ... }
    pub fn created_at(&self) -> &str { ... }
    pub fn dir(&self) -> &Path { ... }
    pub fn recipe(&self) -> &str { ... }
    pub fn schema_version(&self) -> u32 { ... }
}
```

### 3. `load_voice` dispatch

```rust
pub fn load_voice(name: &str) -> Result<VoiceProfile> {
    let canonical = ... ;  // existing validation + canonicalize
    let profile_path = canonical.join("profile.toml");
    let raw = std::fs::read_to_string(&profile_path)?;
    let schema = peek_voice_schema_version(&raw, &profile_path)?;
    match schema {
        1 => {
            let mut v1: VoiceProfileV1 = toml::from_str(&raw)?;
            if !KNOWN_RECIPES_V1.contains(&v1.recipe.as_str()) {
                bail!("v1 voice {name:?} recipe {:?} not in KNOWN_RECIPES_V1",
                      v1.recipe);
            }
            // Populate skip'd fields + assert paths exist (existing logic)
            Ok(VoiceProfile::V1(v1))
        }
        2 => {
            let mut v2: VoiceProfileV2 = toml::from_str(&raw)?;
            if !KNOWN_RECIPES_V2.contains(&v2.recipe.as_str()) {
                bail!("v2 voice {name:?} recipe {:?} not in KNOWN_RECIPES_V2",
                      v2.recipe);
            }
            v2.dir = canonical.clone();
            v2.ref_wav = canonical.join("ref.wav");
            v2.ref_txt = canonical.join("ref.txt");
            assert_path_exists(&v2.ref_wav, "ref.wav")?;
            assert_path_exists(&v2.ref_txt, "ref.txt")?;
            // Note: voice dir MAY contain a sibling .v1.bak/ from a
            // future migration; load_voice tolerates it (doesn't walk).
            Ok(VoiceProfile::V2(v2))
        }
        other => bail!(
            "voice {name:?} profile.toml schema_version={other} unsupported \
             (known: 1, 2). Re-clone or check for typo."
        ),
    }
}
```

### 5. `scripts/clone_voice_fish.sh` (~150 LoC)

Mirrors v1 structure with v2 differences:

```
1. Argument parse: <name> <local_path> <force_flag>
2. Read schema-2 INSTALLED.toml for venv_path + repo_path
3. Source: convert to 32 kHz mono PCM_16 WAV via ffmpeg
4. Duration check:
     duration < 8s   -> die("ref clip must be >= 8s, got {Xs}")
     8s <= dur <= 30s -> use as-is
     duration > 30s  -> middle-trim to min(dur-10s, 20s) seconds,
                        skipping first 5s and last 5s
5. Stage into voices/<name>.partial/
6. Copy trimmed clip -> voices/<name>.partial/ref.wav
7. Whisper-base transcribe ref.wav -> ref.txt
8. Write voices/<name>.partial/profile.toml (schema_version=2,
   recipe=fish-speech-s2-pro, populated fields)
9. Atomic rename: voices/<name>.partial/ -> voices/<name>/
10. Print success summary; next-step hint:
    voiceforge say --voice <name> --text "..."
```

Phase-line contract (mirrors install_cloning_fish.sh `==>` markers
so the same parser-style test in tests/clone_v2_script.rs covers
the assertion contract):

```
==> voiceforge clone <name> (fish-speech S2 Pro recipe)
==> reading schema-2 marker
==> staging into voices/<name>.partial/
==> transcoding to 32 kHz mono PCM_16
==> duration check + middle-trim
==> whisper-base transcribe
==> writing schema-2 profile.toml
==> promoting voices/<name>.partial/ -> voices/<name>/
==> done
```

## Cache-key clarification (B2 fix, plan-internal)

Cache keys are NOT salted with recipe; salts are hard-coded
`b"cloning.gpt-sovits-v2"` (tts.rs:788) and
`b"fish-speech.s2-pro"` (tts.rs:1075). A voice migrated from v1 to v2
in PR-C-b will have a fresh fish-speech cache slot (different salt
domain) — that's the structural reason re-synthesis fires, not
"recipe in salt." Documented here so PR-C-b's user-facing migration
message gets the wording right.

## Risks remaining (acceptable)

- The Rust-side post-install smoke synth still hasn't been validated
  end-to-end against a real install (deferred 6d-8). PR-C-a doesn't
  fix that — but it does add the next surface that needs e2e
  validation. The same gated-env e2e test framework should cover
  both eventually.
- `pack_is_installed` is called both from `packs::install_pack` and
  now `clone::run` pre-flight. Two call sites; same check. If the
  pack-side check ever drifts (e.g., looks at a different on-disk
  marker), clone's check might miss collisions. Acceptable for v0.4;
  consolidate to one place in v0.5.
