# PR-D: `voiceforge note <input>` — long-form narration

**Branch**: `feat/v0.4-pr-d-note-cli` off main (post PR-C-b merged at `8ea48f7`).
**Sprint**: v0.4 (the audiobook killer demo).
**Plan version**: v2 (folds 10 rust-expert REVISE items from v1).

## Goal

User runs `voiceforge note --voice tyson --in chapter.md --out chapter.wav`,
goes to sleep, wakes up to a finished narration in Tyson's voice. Ctrl-C
mid-render is safe: the next run picks up where it left off via a resume
cache.

## Non-goals

- No streaming output.
- No multi-voice casts in one note (use `voiceforge cast`).
- No SSML / per-paragraph direction.
- No auto-migrate of v1 voices. Bail with a hint at the PR-C-b
  `voiceforge voices migrate` command.

## Architecture decisions (locked from rust-expert v1 review)

- **Sample rate is 44.1 kHz mono PCM_16**, not 32 kHz. Fish-speech S2
  Pro emits 44.1 kHz at `scripts/fish_speech_synth.py:220`. The concat
  demuxer is sample-accurate only if every chunk has identical
  codec/SR/channels, so we verify per-chunk format via `hound::WavReader::spec()`
  before emitting `concat_list.txt`, and bail loud on mismatch
  (rust-expert S1).
- **Markdown stripping uses `pulldown-cmark`**, not hand-rolled regex.
  CommonMark-correct text extraction is too error-prone in hand-rolled
  form for the audiobook demo (rust-expert B1 / Q4). Adding the dep
  to `Cargo.toml`.
- **ffmpeg comes from the pinned `ffmpeg6_prefix`** in
  `InstallStateV2` (`apps/voiceforge-cli/src/install_cloning.rs:254`),
  not `$PATH`. Random user ffmpeg versions handle S2 Pro output
  differently (rust-expert B2).
- **Cancel-safety**: Ctrl-C is checked between chunks only.
  `speak_with_explicit_ref` holds a python-child mutex and writes
  NDJSON; cancelling mid-await leaves the child with a stale response
  in its stdout pipe, poisoning the next request (rust-expert B4). The
  orchestrator installs a `Arc<AtomicBool>` cancel flag,
  `tokio::signal::ctrl_c().await` sets it; the chunk loop checks AFTER
  each chunk completes (or AFTER a skip).
- **Test seam is parametric `note::run_with(synth, args)`**, matching
  the `install_smoke::run_smoke_test_with` precedent. NO env-var-gated
  mock; the production binary has zero test-only knobs (rust-expert
  Q2 / Option A).
- **Resume cache key invariants**: `(input_sha256, voice,
voice_created_at, voice_recipe, total_chunks, chunker_version)`.
  Any mismatch bails with a clear hint at `--force` or a fresh
  `--out` path (rust-expert S2 / S3).
- **`chunker_version`** is a `const CHUNKER_VERSION: u32 = 1;` in
  `note.rs`. Bumped on any change to `chunk_text`. Stored in
  progress.json + included in `chunk_sha256` salt so a chunker
  refactor invalidates the cache.
- **Chunk write ordering**: `<chunk>.wav.tmp` → fsync → `rename →
<chunk>.wav` → fsync the chunk → write `progress.json.tmp` → fsync
  → `rename → progress.json`. This guarantees: progress.json names a
  chunk ⇒ that chunk's bytes are durably on disk (rust-expert B3).

## CLI surface

```
voiceforge note --voice <name> [--in <file>] [--out <file>] [--force] [--cleanup]
```

| Flag        | Required                       | Default                | Meaning                                                                                                                      |
| ----------- | ------------------------------ | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `--voice`   | yes                            | —                      | Voice name. MUST be v2 (bail on v1).                                                                                         |
| `--in`      | no                             | stdin                  | Input. `.md` files are markdown-stripped via pulldown-cmark; `.txt` is paragraph-split only. Stdin is treated as raw `.txt`. |
| `--out`     | required when `--in` is a path | `note_<timestamp>.wav` | Output WAV path.                                                                                                             |
| `--force`   | no                             | false                  | Bypass progress.json check + re-synth all chunks. Existing chunk WAVs are overwritten in place.                              |
| `--cleanup` | no                             | false                  | rm `<out>.chunks/` and `<out>.progress.json` on success.                                                                     |

The struct field is `input: Option<PathBuf>` (not `in`) — `in` is a
Rust keyword (rust-expert A3). CLI exposes it as `--in` via
`#[arg(long = "in")]`.

Exit codes:

- 0: WAV written.
- 1: any error.
- 2: voice not found / on schema 1 (bail with migrate hint).

### Stdin + resume incompatibility

Per rust-expert B7 option (a): if `--in` is stdin AND `<out>.progress.json`
exists, bail with "`--in` from stdin doesn't support resume. Re-run
with `--in <file>` or delete `<out>.progress.json` and retry."

### Empty / all-markdown input

Per rust-expert B6: if `chunk_text(raw)` returns an empty Vec
(empty file, whitespace-only, all-code-block), bail up front with
"input has no narrate-able text after markdown stripping".

## Chunking (pure, unit-testable)

```rust
const CHUNKER_VERSION: u32 = 1;
const CHUNK_MAX_CHARS: usize = 500;

pub struct Chunk {
    pub text: String,
    pub sha256: String,   // hex; salt = (CHUNKER_VERSION, voice, created_at, recipe, text)
    pub index: usize,
}

pub fn chunk_text(raw: &str, voice: &str, created_at: &str, recipe: &str) -> Vec<Chunk>;
pub fn chunk_sha256(chunker_version: u32, voice: &str, created_at: &str, recipe: &str, text: &str) -> String;
```

Pipeline:

1. **Detect markdown** by `--in` extension (`.md` / `.markdown` =
   markdown; everything else + stdin = plain text). Plain-text path
   skips pulldown-cmark and just paragraph-splits.
2. **Markdown strip via `pulldown-cmark::Parser::new(raw)`**:
   iterate events, accumulate `Event::Text(...)` content, drop
   everything inside `Tag::CodeBlock` / `Tag::Image` events
   (track the open/close pair with a depth counter), emit `\n\n`
   between top-level block ends so paragraph structure survives.
3. **Normalize**: collapse internal whitespace runs to a single
   space; CRLF → LF; preserve `\n\n+` as paragraph delimiter.
4. **Split paragraphs** on `\n\n+`.
5. **Long-paragraph split**: paragraphs > `CHUNK_MAX_CHARS` get
   recursively split at the last `[.!?]\s+` that fits the budget.
   Fallback: hard split at `CHUNK_MAX_CHARS` if no sentence boundary
   exists (rust-expert R4: prevents the recursive-loop case on a
   single 10k-char paragraph with no punctuation).
6. **Emit `Chunk { text, sha256, index }`**. `chunk_sha256` is
   `sha2::Sha256` over a canonical separator-joined byte string:
   `format!("{CHUNKER_VERSION}\n{voice}\n{created_at}\n{recipe}\n{text}")`.

## Resume cache: `<out>.progress.json`

```json
{
  "version": 1,
  "chunker_version": 1,
  "voice": "tyson",
  "voice_created_at": "2026-05-04T00:00:00Z",
  "voice_recipe": "fish-speech-s2-pro",
  "input_sha256": "<sha256 of raw bytes BEFORE markdown strip>",
  "total_chunks": 12,
  "completed": [
    { "index": 0, "sha256": "...", "wav_path": "<out>.chunks/chunk_0000.wav" }
  ]
}
```

`#[serde(deny_unknown_fields)]` so future fields trip an explicit error
that points users at `--force`. `version: u32` for forward-compat — the
loader bails on unknown values with a "use `--force` to start fresh"
hint (rust-expert A2).

Bail conditions on resume:

- `version != 1` → bail (run with `--force`).
- `chunker_version != CHUNKER_VERSION` → bail.
- `voice` / `voice_created_at` / `voice_recipe` mismatch → bail.
- `input_sha256` mismatch → bail with "input file changed between
  runs; use `--force` or fresh `--out` path".
- `total_chunks` mismatch → bail (rust-expert S2: catches a chunker
  refactor that didn't bump `chunker_version`).

Per-chunk replay rules (only run if all the above match):

- For each `completed[i]`: if `wav_path` is missing → re-synth
  (rust-expert R2). If `sha256` mismatches the recomputed chunk
  sha → re-synth.

## Concat pipeline

After every chunk is written:

1. **Per-chunk format verification** (rust-expert S1): open each
   `chunk_NNNN.wav` via `hound::WavReader`, assert
   `spec.channels == 1`, `spec.sample_rate == 44_100`,
   `spec.bits_per_sample == 16`, `spec.sample_format == Int`. Bail
   loudly on mismatch (names the bad chunk, suggests `--force`).
2. **Write `<out>.chunks/concat_list.txt`** with relative-path
   entries:
   ```
   file 'chunk_0000.wav'
   file 'chunk_0001.wav'
   ```
   Every filename is the hard-coded `chunk_{:04}.wav` literal — no
   user-controlled string enters the file, so the single-quote
   quoting is safe by construction (rust-expert B5).
3. **Run** (using the pinned ffmpeg from `InstallStateV2`):
   ```
   <ffmpeg6_prefix>/bin/ffmpeg \
     -hide_banner -loglevel error -y \
     -f concat -safe 0 \
     -i <out>.chunks/concat_list.txt \
     -c copy <out>
   ```
4. **Cleanup** (if `--cleanup`): rm `<out>.chunks/`, rm
   `<out>.progress.json`. Print final WAV path + duration.

## FishEngine integration

`note.rs` defines:

```rust
#[async_trait::async_trait]
pub trait NoteSynth: Send + Sync {
    /// Synthesize `text` to `out` (writes a 44.1 kHz mono PCM_16 WAV).
    /// Ref clip + transcript are constructor params on the impl,
    /// not per-call args — they're constant per `note::run`.
    async fn synth(&self, text: &str, out: &Path) -> Result<()>;
}

pub struct FishEngineNoteAdapter {
    engine: FishEngine,
    ref_wav: PathBuf,
    ref_txt: String,
}

#[async_trait::async_trait]
impl NoteSynth for FishEngineNoteAdapter {
    async fn synth(&self, text: &str, out: &Path) -> Result<()> {
        self.engine.speak_with_explicit_ref(text, &self.ref_wav, &self.ref_txt, out).await
    }
}
```

`FishEngineNoteAdapter::from_v2(profile: &VoiceProfileV2)` is the
canonical constructor — reads ref.txt into a String, owns the engine,
holds the ref.wav path.

**Note on `SmokeSynth` (rust-expert A1)**: `install_smoke::SmokeSynth`
has a similar shape but is per-call ref-parameterized (it's used in a
one-shot smoke that doesn't have a persistent voice context). We
deliberately diverge: `NoteSynth::synth` has no ref args because for
`note::run` they're constant. Documented in a comment in `note.rs` to
prevent a future merge attempt.

## Orchestrator: `note::run` + `note::run_with`

```rust
pub struct NoteArgs {
    pub voice: String,
    pub input: Option<PathBuf>,    // None = stdin
    pub output: PathBuf,
    pub force: bool,
    pub cleanup: bool,
}

/// Production entry: constructs FishEngineNoteAdapter, calls run_with.
pub async fn run(args: NoteArgs) -> Result<()>;

/// Testable entry: takes any NoteSynth.
pub async fn run_with<S: NoteSynth + ?Sized>(
    synth: &S,
    voice_profile: &VoiceProfileV2,
    args: &NoteArgs,
) -> Result<()>;
```

Per-chunk loop sketch (cancel-safe, rust-expert B4):

```rust
let cancel = Arc::new(AtomicBool::new(false));
{
    let c = cancel.clone();
    tokio::spawn(async move {
        if tokio::signal::ctrl_c().await.is_ok() {
            c.store(true, Ordering::SeqCst);
        }
    });
}

for chunk in chunks.iter() {
    if cancel.load(Ordering::SeqCst) {
        bail!("cancelled — resume with the same args");
    }
    if already_done(chunk, &progress) { progress_bar.inc(1); continue; }
    let chunk_tmp = chunk_wav_tmp(&out_chunks_dir, chunk.index);
    let chunk_final = chunk_wav_final(&out_chunks_dir, chunk.index);
    synth.synth(&chunk.text, &chunk_tmp).await?;
    fsync(&chunk_tmp)?;
    fs::rename(&chunk_tmp, &chunk_final)?;
    fsync_path(&chunk_final)?;            // fsync the renamed inode
    progress.add(chunk.index, chunk.sha256.clone(), chunk_final.clone());
    write_progress_atomically(&progress, &progress_path)?;
    progress_bar.inc(1);
}
```

Cancel is checked ONLY at the top of each iteration, never inside the
`synth.synth().await`. If a Ctrl-C lands mid-synth, the python child's
response comes back and is read into the void of the dropped future;
that's bad. We _can't_ prevent that without `speak_with_explicit_ref`
being cancel-safe (which it isn't), so we just don't `select!` over
the synth await. Documented in code comment.

  S1). Added per-chunk format verification via `hound` before concat.
- Resume cache key extended with `input_sha256`, `total_chunks`,
  `chunker_version` (rust-expert S2 / S3).
